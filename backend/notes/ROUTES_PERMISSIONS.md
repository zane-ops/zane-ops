# Routes & Permissions

Current state of the backend API, generated by introspecting the Django URL resolver (`ENABLE_EE=true`). 137 routes total. Paths are normalized (regex groups → `{param}`, trailing `/?` dropped). Methods listed are the handlers actually reachable after `http_method_names` filtering.

## Role model

`WorkspaceRole` ([models/main.py:79](../zane_api/models/main.py#L79)) is an ordered integer scale — every check is `role >= X`, so higher roles inherit everything below.

| Role | Value | Permission class |
| --- | --- | --- |
| Viewer | 10 | `IsWorkspaceViewer` |
| Member | 30 | `IsWorkspaceMember` |
| Admin | 40 | `IsWorkspaceAdmin` |
| Owner | 50 | `IsWorkspaceOwner` |
| Instance superuser | — | `IsInstanceOwner` (`user.is_superuser`) |

Other permission classes ([permissions.py](../zane_api/permissions.py)):

- `HasWorkspace` — resolves the active workspace from the session onto `request.workspace`; paired with every workspace-role check.
- `InternalZaneAppPermission` — Basic auth with `zaneops:$SECRET_KEY`, for internal agents (fluentd).
- `AllowAny` / `IsAuthenticated` — DRF built-ins.

The DRF default (`settings.REST_FRAMEWORK.DEFAULT_PERMISSION_CLASSES`, [settings.py:294](../backend/settings.py#L294)) is **`[HasWorkspace, IsWorkspaceViewer]`**. Five views rely on it rather than declaring their own: `SettingsView`, `SwitchWorkspaceAPIView`, `WorkspaceLeaveAPIView`, `ProjectServiceListAPIView`, `HttpLogsFieldsAPIView`.

## Project scoping

`get_accessible_projects()` / `aget_accessible_projects()` narrow queryset access on top of the role check: **Member and above see every project in the workspace; a Viewer only sees the projects listed in `membership.accessible_projects`** (empty for users with no membership). Used by the projects, environments, shared-variables and service views.
